# Documentation Instructions

These rules apply to docs.

## Priorities

Document product scope, user outcomes, system boundaries, data flow, tenant assumptions, RAG contracts, evaluation, deployment prerequisites, pilot gates, cost limits, and rollback.

Keep documents tied to code that exists. Mark proposals, assumptions, and verified behavior separately.

## Writing rules

- Use concrete factory workflows.
- Prefer tables, short procedures, and diagrams.
- Include owner, status, date, evidence, and next decision where useful.
- Do not publish secrets, private tenant data, unsupported claims, or invented factory metrics.
- Update the nearest document instead of creating duplicates.

## Roadmap discipline

Every feature proposal states the user problem, smallest usable slice, data and authorization needed, cost and operational burden, success metric, and rollback or deferral condition.
